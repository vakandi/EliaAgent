## 🔍 ACCFORGE BUG INVESTIGATION

### Bug Report (from DegenJuice - Discord)
> "Deposits work but return link is wrong (links to socialmedia.store) and money doesn't get credited to accounts"

### Root Cause Identified

**Location:** `/Users/vakandi/Documents/AccForge/backend/services/core/payment_service.py`

**Lines 601, 610, 621:**
```python
# STRIPE default
"return_url": getattr(app.state, "STRIPE_RETURN_URL", os.getenv("STRIPE_RETURN_URL", "https://socialmediatraining.store/payment/success")),

# PAYPAL default  
"return_url": getattr(app.state, "PAYPAL_RETURN_URL", os.getenv("PAYPAL_RETURN_URL", "https://socialmediatraining.store/payment/success")),

# FREEKASSA default
"return_url": getattr(app.state, "FREEKASSA_RETURN_URL", None) or os.getenv("FREEKASSA_RETURN_URL", "https://socialmediatraining.store/payment/success"),
```

**Issue:** The return URLs are hardcoded to `socialmediatraining.store` as fallback defaults instead of the correct store domain.

**Solution:** These payment providers need to receive the correct `return_url` from the frontend checkout request, OR the environment variables need to be set to the correct domain (e.g., `https://accforge.io` or the actual store making the request).

### Credit Issue
The "money doesn't get credited" issue likely needs investigation in the payment callback handlers (`routers/payments_*.py`).
